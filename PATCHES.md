# TBG carried patches (`tbg-patches`)

This fork is **upstream tip + a short stack of TBG patches**. Policy
(2026-06-12): we do **not** open upstream PRs — all changes land here.
Divergence is kept cheap by discipline instead:

- Patches must be **additive and upstream-shaped** (no schema forks, no
  API breaks, tests in upstream conventions) so rebases stay trivial.
- On a version bump: rebase this branch onto the new upstream tag,
  re-play the stack, and **drop any patch** whose drop condition below is
  met. Never merge upstream into this branch.
- Every patch gets a row here when it lands. A patch without a documented
  drop condition is a review failure.
- Consumers pin a commit, not the branch: bump `GBRAIN_REF` in
  `tbg-brain-workspace/Dockerfile` deliberately after a rebase.

| Patch (first commit) | What / why | Drop when |
|---|---|---|
| `fix(ingest): log ingest event on capture/put_page write-through` (TBG-267) | Capture-based ingestion (slack/linear/meeting → `gbrain capture`) never wrote `ingest_log`, freezing `get_ingest_log` freshness at the last import while daily captures kept landing. | Upstream ships ingest-log writes on the capture/put_page path. |
| `docs(meeting-sync): fix transcript format + facts-extraction gotchas` (TBG-267) | Upstream doc described a transcript format the facts extractor rejects. | Upstream corrects the doc. |
| `feat(minions): subagent read federation + owner-scoped get_agent_job` (fork PR #1, TBG-274 / ADR-0004) | Dispatched subagent tool reads were pinned to source `default` (blind on pods whose content lives in `linear`/`slack`/`<client>` sources); `agent`-scope dispatch clients had no op to retrieve their own job results. Threads the dispatching client's `federated_read` into the tool context (`OperationContext.allowedSources`) and adds owner-checked `get_agent_job`. | Upstream ships minions "Phase 2" multi-tenant dispatch (per its `docs/designs/MINIONS_AGENT_ORCHESTRATION.md`) with equivalent read federation + owner-scoped retrieval. |
| `feat(minions): thread bound_source_id into subagent put_page writes` (fork PR #3, TBG-278 Stage 1) | `submit_agent` stamped `source_id` job data from the client's `bound_source_id`, but `buildOpContext` hardcoded the write authority to `'default'` — agent writes ignored the binding, defeating source-level isolation of commissioned drafts (found live: a write bound to source `commissions` landed in `default`, where every reader federates). Threads `data.source_id` → `buildBrainTools` → `OperationContext.sourceId`; unset still means `'default'`. | Upstream wires `bound_source_id` through the subagent write path (same Phase 2 condition as the read-federation patch). |
| `feat(autopilot): config-driven cycle phase exclusion` (fork PR #4, TBG-281) | The every-tick autopilot cycle runs `ALL_PHASES`, including `propose_takes` which re-scans the 50 most-recent pages every run (idempotent output, full LLM input each time) — ~$150/day across a hot fleet for ~0 new output. Adds `resolveCyclePhases()` reading `autopilot.exclude_phases` (comma-separated; default unset → null → unchanged ALL_PHASES) and stamps the reduced list onto autopilot-cycle jobs. Heavy phases then run only via the nightly `gbrain dream --phase X` crons (which bypass the fanout). Config-driven so the exclusion list retunes without a rebuild. | Upstream gains a way to keep discretionary LLM phases off the always-on cycle (e.g. a per-phase cadence or an autopilot phase-allowlist). |
| `feat(budget): backend spend observability` (fork PR #5, TBG-281 Phase A) | Autopilot cycle + dream crons run with no OAuth client, so their LLM spend never reached `mcp_spend_log` — the per-brain backend daily cost was invisible (how the propose_takes re-scan ran ~$700/day undetected). Adds `withBackendSpendTracking()` (installs an UNCAPPED observation BudgetTracker when none is in scope; records cumulative spend to `mcp_spend_log` under a `@service:*` client_id; no-clobber guard preserves CLI `--max-cost`). Wrapped at the `dream` command + autopilot-cycle handler. Observation only — no enforcement (Phase B adds a per-brain cap). | Upstream ships per-brain backend spend accounting / a service-identity cost ledger. |
| `feat(takes): make propose_takes model config-driven` (fork PR #6, TBG-281) | `propose_takes` was the only cycle phase that hardcoded its model id (`'claude-sonnet-4-6'`, in two places in the phase wrapper) instead of routing through `resolveModel`, so its model couldn't be retuned without a rebuild and it ignored gbrain's own `models.dream.takes` / `models.tier.reasoning` / `models.default` precedence. Routes the call through `resolveModel({configKey: 'models.dream.takes', tier: 'reasoning', fallback: 'sonnet'})` — **behavior-neutral** (default resolves to the same Sonnet) and `opts.model` still wins for tests/overrides. Mirrors how `synthesize`/`patterns`/facts-extraction already resolve their model; gives operators a knob to retune (or to throttle by config) without forking behavior. | Upstream makes `propose_takes` resolve its model via `resolveModel`/config like the other phases. |
